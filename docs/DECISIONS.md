# Decisions log

Short ADR-style log. Add new entries at the bottom: `D-0NN — decision — why`.

| D-004 | One published package, **`@puranderdua/ui`**, that also ships `foundations.css` (tokens + `@theme` bridge + recipes). No separate tokens package.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Fewer moving parts; one version to pin.                                                                                       |
| D-005 | Consumers must use Tailwind v4. The package ships CSS source; consumers add `@source` for the package `dist`. | D-006 | Button adopted from shadcn/ui, adapted to tokens. Variants `primary`, `secondary`; sizes `sm`, `md`. | D-007 | Registry: static shadcn registry on Vercel; fixed version paths `/r/v0.1.0/` plus `/r/latest/`; namespace `@puranderdua`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Real remote installs; reproducible pins.                                                                                      |
| D-008 | `ds-foundations` is a single `foundations.css` file, byte-identical to the package's `foundations.css`. A consumer imports it **once**, from whichever channel it uses. CI checks the two are identical.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Prevents tokens being defined twice in a consumer that uses both channels.                                                    |
| D-009 | Consumer site: Next.js App Router on Vercel. Text/Heading come from npm `@puranderdua/ui@0.1.0` (pinned). Button comes via `shadcn add @puranderdua/ds-button`. A lint rule bans importing Button from the package in the site.                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Proves both channels on a real site.                                                                                          |
| D-010 | Button click outcome on the site: `alert("Button clicked")`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Simple, verifiable outcome; Playwright handles the dialog.                                                                    |
| D-011 | Clean-install proof is a script (`scripts/clean-install.sh`) that creates a fresh Next app outside the repo, not a permanent fixture app.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Cheaper than the blueprint's reverse-path fixture; still proves no monorepo-only shortcuts.                                   |
| D-012 | Process: branch per milestone, commit per session, PR per milestone, CI must pass before merge.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Lightweight stand-in for the blueprint's per-task human approval.                                                             |
| D-013 | Penpot (hosted) is a light visual reference only: imported tokens plus one specimen board. No sync automation.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Blueprint parity on intent, minimal cost.                                                                                     |
| D-014 | If short on time, cut in this order: Penpot → Storybook → clean-install script → update/rollback tests.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Agreed cut order.                                                                                                             |
| D-015 | AI may commit, push milestone branches and create/edit PRs; Purander alone merges PRs. AI never force-pushes, pushes `main`, tags, deploys or publishes to npm.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Faster iteration while keeping final authority over what lands.                                                               |
| D-016 | Primary color `#595959` (neutral gray), font Inter.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Brand choice at S1; gray gives ~7:1 on white.                                                                                 |
| D-017 | Token keys never contain `.`; fractional spacing uses a hyphen (`space.1-5`). Font family is one stack token `font.family.sans`; line-height is unitless.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | `.` separates alias paths; unitless line-height scales with font size.                                                        |
| D-018 | Added primitive `size.control.{sm,md}` (2rem, 2.5rem) and semantic `focus.ring-width`, `focus.ring-offset`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Control heights aren't on the spacing scale; components may only use semantic tokens.                                         |
| D-019 | `validate-tokens` enforces: primitives hold raw values, semantics hold aliases to primitives only (no semantic→semantic).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Keeps the tier rule mechanical.                                                                                               |
| D-020 | Style Dictionary pinned to v4 (`^4.4`, `usesDtcg: true`); typography composites expand to per-property vars via `expand.include: ["typography"]`. Generated `tokens.css` and `tokens.json` are committed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | v5 is current on npm, but the plan specifies v4. Committed output lets `tokens:check` catch stale builds.                     |
| D-021 | `tokens:check` = validate-tokens, rebuild into a temp dir and diff against committed output, then WCAG AA 4.5:1 contrast on resolved colors (text, primary incl. hover/active, secondary incl. hover/active). Contrast needed no token changes.                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Mechanical, deterministic gate in `pnpm check` and CI.                                                                        |
| D-022 | `pnpm-workspace.yaml` `allowBuilds` sets `style-dictionary` and `@bundled-es-modules/glob` to `false`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Neither needs install scripts; stops pnpm 11 failing installs with ERR_PNPM_IGNORED_BUILDS.                                   |
| D-023 | `validate-tokens` also enforces: alias target `$type` matches the referring token (typography parts: fontSize/letterSpacing→dimension, etc.), primitive value formats (`#rrggbb`, number+rem/em/px, integer weight, finite number), and a `$description` on every semantic token.                                                                                                                                                                                                                                                                                                                                                                                                                        | Wrong-type aliases and malformed values used to pass validation and surface only as broken CSS.                               |
| D-024 | Contrast gate also checks 3:1 non-text pairs (focus ring on canvas, secondary border on its three fills). `disabled.*` is exempt and `border.default` is decorative; both are documented in `contrast.mjs`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | WCAG 1.4.11; keeps the exemptions explicit instead of silent.                                                                 |
| D-025 | Palette roles: `brand` (achromatic, D-016) is for interactive accents (actions, focus, secondary border); `neutral` (cool slate) is for text, surfaces, separators and disabled. The slight tint difference is accepted. Naming: primitives `ring.*` / `border-width.*` are raw metrics; components use semantic `focus.ring-*` and `border.default`.                                                                                                                                                                                                                                                                                                                                                    | Keeps brand identity grey while text/surfaces stay readable; revisit if Button visuals look inconsistent in S6.               |
| D-026 | `tokens:check` also runs `scripts/test-token-propagation.mjs`: changing a primitive in a temp copy must change exactly that primitive plus its `var()` dependents in `tokens.json`, and only that one line in `tokens.css`. Build uses a custom `css/variables-ds` format: no repeated descriptions on expanded typography vars, space tokens in numeric order.                                                                                                                                                                                                                                                                                                                                          | Turns the S3 "changing a primitive changes every dependent" check into a regression test.                                     |
| D-027 | Bridge maps semantic vars only, with `-ds-` namespaces: `--color-ds-*`, `--text-ds-<role>` (+ `--line-height`/`--font-weight`/`--letter-spacing` companions), `--font-ds-sans`, `--radius-ds-control`, and `--spacing-ds-control-*` for control height/padding (needed so Button avoids arbitrary values).                                                                                                                                                                                                                                                                                                                                                                                               | Utilities stay token-backed; `inline` keeps values as `var()` refs.                                                           |
| D-028 | Recipes: `.ds-type-<role>` (family + role composite) and `.ds-focus-ring` (outline width/offset have no Tailwind namespace). `playground:check` is part of `pnpm check`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Composites utilities can't express in one class; mechanical proof the built CSS contains every class.                         |
| D-029 | `cn` is `twMerge(clsx())` with `extendTailwindMerge` registering the `text-ds-<role>` font sizes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Without it, tailwind-merge treats `text-ds-body` as a colour and drops it when merged with `text-ds-text-muted`.              |
| D-030 | Text/Heading classes: base `text-ds-text` + `ds-type-<role>` recipe; caption adds `text-ds-text-muted`. Heading default element comes from a static map (`display`→h1); default variant is `h1`. Tests use `vite-tsconfig-paths` as specified, though Vite 8 can do it natively (`resolve.tsconfigPaths`).                                                                                                                                                                                                                                                                                                                                                                                               | Recipes already carry size/weight/leading/tracking; map keeps `as` independent of `variant`.                                  |
| D-031 | Review of Text/Heading (external, 2026-10-17): adopted JSX, `data-slot`, element-specific props/ref types for `Text` (`htmlFor` only on `as="label"`). Superseded in part by D-033 (React 19 only, no `forwardRef`; `cn()` now dedupes `ds-type-*`). `label` stays in `Text`'s `as` (form elements will follow).                                                                                                                                                                                                                                                                                                                                                                                         | Idiomatic and typed API without dropping React 18 or the S5 spec.                                                             |
| D-032 | `textVariants` no longer has a shared base colour: each variant carries its own (`text-ds-text` or `text-ds-text-muted`). `cn` has unit tests, including one that fails if a `--text-ds-*` size in `theme.css` is missing from the `tailwind-merge` extension. axe's canvas probe is stubbed in test setup (contrast is covered by `tokens:check`).                                                                                                                                                                                                                                                                                                                                                      | Raw `textVariants()` output (public export) had two competing colour utilities; the hand-kept size list could silently drift. |
| D-033 | React 19 only: peer deps `^19`, no `forwardRef`, `ref` is a plain prop. `ref` is typed by `StrictRef` (`src/lib/types.ts`) because React's `RefCallback` is bivariant; type tests (`ref-types.test.tsx`) use `@ts-expect-error`. TypeScript still can't separate p/span/div object refs (identical DOM interfaces, covariant `RefObject`). `cn()` treats `ds-type-*` as one group (later wins, so `className` overrides `variant`) and a recipe replaces earlier loose type utilities. The `text-ds-*` size and `ds-type-*` lists are generated from `theme.css` into `src/lib/generated/ds-classes.ts` by `build-foundations`, with a test that fails if they go stale. `label` stays in `Text`'s `as`. | Decisions from Purander's review; removes the hand-kept lists and the "use variant not className" caveat.                     |

# Decisions log

Short ADR-style log. Add new entries at the bottom: `D-0NN — decision — why`.

| ID    | Decision                                                                                                                                                                                                                                        | Why                                                                                                       |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| D-001 | One monorepo `ui-design-system`, pnpm workspaces. No multi-agent infra, so no `.agents/`, adapters or sync scripts.                                                                                                                             | Solo build with AI assistance; blueprint B0 track dropped.                                                |
| D-002 | Release 0 scope: Typography (Text, Heading) and Button through all 4 tiers.                                                                                                                                                                     | Same as blueprint v6; breadth comes later.                                                                |
| D-003 | Canonical tokens: DTCG JSON → Style Dictionary v4 → `--ds-*` CSS variables.                                                                                                                                                                     | Portable source of truth, not tied to Tailwind or Penpot.                                                 |
| D-004 | One published package, **`@puranderdua/ui`**, that also ships `foundations.css` (tokens + `@theme` bridge + recipes). No separate tokens package.                                                                                               | Fewer moving parts; one version to pin.                                                                   |
| D-005 | Consumers must use Tailwind v4. The package ships CSS source; consumers add `@source` for the package `dist`. No precompiled Tailwind CSS.                                                                                                      | Avoids clashing base styles; shadcn requires Tailwind anyway.                                             |
| D-006 | Button adopted from shadcn/ui, adapted to tokens. Variants `primary`, `secondary`; sizes `sm`, `md`. Provenance in `docs/provenance/button.md`.                                                                                                 | Proven accessible base; still fully owned source.                                                         |
| D-007 | Registry: static shadcn registry on Vercel; fixed version paths `/r/v0.1.0/` plus `/r/latest/`; namespace `@puranderdua`.                                                                                                                       | Real remote installs; reproducible pins.                                                                  |
| D-008 | `ds-foundations` is a single `foundations.css` file, byte-identical to the package's `foundations.css`. A consumer imports it **once**, from whichever channel it uses. CI checks the two are identical.                                        | Prevents tokens being defined twice in a consumer that uses both channels.                                |
| D-009 | Consumer site: Next.js App Router on Vercel. Text/Heading come from npm `@puranderdua/ui@0.1.0` (pinned). Button comes via `shadcn add @puranderdua/ds-button`. A lint rule bans importing Button from the package in the site.                 | Proves both channels on a real site.                                                                      |
| D-010 | Button click outcome on the site: `alert("Button clicked")`.                                                                                                                                                                                    | Simple, verifiable outcome; Playwright handles the dialog.                                                |
| D-011 | Clean-install proof is a script (`scripts/clean-install.sh`) that creates a fresh Next app outside the repo, not a permanent fixture app.                                                                                                       | Cheaper than the blueprint's reverse-path fixture; still proves no monorepo-only shortcuts.               |
| D-012 | Process: branch per milestone, commit per session, PR per milestone, CI must pass before merge.                                                                                                                                                 | Lightweight stand-in for the blueprint's per-task human approval.                                         |
| D-013 | Penpot (hosted) is a light visual reference only: imported tokens plus one specimen board. No sync automation.                                                                                                                                  | Blueprint parity on intent, minimal cost.                                                                 |
| D-014 | If short on time, cut in this order: Penpot → Storybook → clean-install script → update/rollback tests.                                                                                                                                         | Agreed cut order.                                                                                         |
| D-015 | AI may commit, push milestone branches and create/edit PRs; Purander alone merges PRs. AI never force-pushes, pushes `main`, tags, deploys or publishes to npm.                                                                                 | Faster iteration while keeping final authority over what lands.                                           |
| D-016 | Primary color `#595959` (neutral gray), font Inter.                                                                                                                                                                                             | Brand choice at S1; gray gives ~7:1 on white.                                                             |
| D-017 | Token keys never contain `.`; fractional spacing uses a hyphen (`space.1-5`). Font family is one stack token `font.family.sans`; line-height is unitless.                                                                                       | `.` separates alias paths; unitless line-height scales with font size.                                    |
| D-018 | Added primitive `size.control.{sm,md}` (2rem, 2.5rem) and semantic `focus.ring-width`, `focus.ring-offset`.                                                                                                                                     | Control heights aren't on the spacing scale; components may only use semantic tokens.                     |
| D-019 | `validate-tokens` enforces: primitives hold raw values, semantics hold aliases to primitives only (no semantic→semantic).                                                                                                                       | Keeps the tier rule mechanical.                                                                           |
| D-020 | Style Dictionary pinned to v4 (`^4.4`, `usesDtcg: true`); typography composites expand to per-property vars via `expand.include: ["typography"]`. Generated `tokens.css` and `tokens.json` are committed.                                       | v5 is current on npm, but the plan specifies v4. Committed output lets `tokens:check` catch stale builds. |
| D-021 | `tokens:check` = validate-tokens, rebuild into a temp dir and diff against committed output, then WCAG AA 4.5:1 contrast on resolved colors (text, primary incl. hover/active, secondary incl. hover/active). Contrast needed no token changes. | Mechanical, deterministic gate in `pnpm check` and CI.                                                    |
| D-022 | `pnpm-workspace.yaml` `allowBuilds` sets `style-dictionary` and `@bundled-es-modules/glob` to `false`.                                                                                                                                          | Neither needs install scripts; stops pnpm 11 failing installs with ERR_PNPM_IGNORED_BUILDS.               |

# Production-readiness audit — 2026-10-20

Review of the whole repository after S25 (`@puranderdua/ui@0.4.0`, PR #26), against React, JS/TS, accessibility, security, semantic HTML, architecture and frontend system-design practice. It found 5 blockers and 36 other findings. Every finding is fixed in milestone **MH Production hardening** (H1–H10, D-068) before S26 starts.

**How to use this register:** each H-session fixes the IDs its prompt names and sets their status here to `fixed in H<n>` with the evidence (test name, command, measured value). A finding may only be closed as `accepted` with a decision reference. H10 verifies every row and closes the audit; the register must have no `open` rows before S26 (D-070).

Severity: **Blocker** (no production release), **High** (fix before more components are built on it), **Med**, **Low**.

## Already solid (keep)

- Strict TypeScript with `noUncheckedIndexedAccess`; `StrictRef` rejects mismatched callback refs.
- Static variant maps; no dynamic class names, no arbitrary values; logical properties.
- Alias-only semantic layer with completeness and contrast gates, built per theme.
- Per-component `"use client"` build, verified against a real Next app.
- Rendered layout tests in a real browser; axe in site e2e; skip link; reduced motion; outline focus ring (works in forced-colours mode).
- No `any`, `@ts-ignore`, `dangerouslySetInnerHTML` or `eval` in shipped code.

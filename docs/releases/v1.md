# Release 1 notes

Release 1 turned a three-component package into a themed design system: one npm channel, a category-wise showcase, four themes and a theme playground. The package is **`@puranderdua/ui@0.8.0`** (0.2.0 → 0.8.0 over eight minors, 2026-10-19 to 2026-11-14). The playground is site-only, so it needed no package release.

## Scope

- **Single channel (D-055).** The shadcn registry is gone from the repo; every component ships through npm, and the site installs the package at a pinned version.
- **Components, five categories.** Typography: Text, Heading. Layout: Container, Grid, Stack, Cluster, Section, Split, Sidebar. Forms: Label, Field, Fieldset, Input, Checkbox, RadioGroup, Select. Actions: Button, Link. Display: Card, Tabs, Banner (plus `ThemeScope`).
- **Themes.** Base, Corporate, Nature, Quirky, each with its own colour, typography, shape, elevation, density, motion and an accent colour. A consumer imports `foundations.css` plus one `themes/<name>.css`. The token manifest reserves a `mode` modifier for dark mode (D-047).
- **Showcase.** `/components` and `/components/[category]` on the site, with a header theme switcher.
- **Playground.** `/playground`: start from a theme, knobs (brand and accent colour, neutral hue and chroma, heading and body font, radius, border width, shadow, density, motion), per-token overrides, live contrast per pair, a themed preview, local persistence, and **export** of the four DTCG files plus the CSS (S35).
- **Production hardening (MH, D-068).** The 2026-10-20 audit's findings were fixed in H1–H10, with guardrails that now run in CI (client-export check, tone-recipe check, contrast matrix, Storybook a11y gate).

## Evidence

- **Round trip (S35).** `apps/site/src/playground/export.test.ts` exports a playground theme, writes the files into a scratch copy of `tokens/themes/custom/`, adds a scratch resolver entry and runs the repo's own `validate-tokens`, `build-tokens` and `contrast` scripts. It covers an unchanged Base, an unchanged Quirky, a state with every knob on Nature (accent included) and a Corporate state; built vars and CSS declarations equal what the playground resolved. A low-contrast export still validates and builds, and `contrast` fails it.
- **`pnpm check`** (what CI runs): lint, per-theme token validation and contrast (200 pairs per theme, all pass), typecheck, unit and a11y tests, package build, client-export check, CSS coverage, rendered layout tests, every story as a browser test with axe, Storybook build. Result of the S35 run is in [PROGRESS.md](../PROGRESS.md).
- **Site e2e** (`pnpm --filter site test:e2e`, Chromium, Firefox, WebKit): axe on every showcase page in every theme and on the playground (default state and with every group open), keyboard, 320px, export downloads and clipboard. S35 run recorded in PROGRESS.md.
- **Package install.** `scripts/check-rsc.sh` (tarball into a fresh Next app, RSC boundary) and `scripts/clean-install.sh` (published package, fresh app) from the earlier sessions; rerun them before the next npm release.
- Contrast, theme direction and sign-off per theme: [`docs/themes.md`](../themes.md). Audit register: [`docs/audits/2026-10-20-production-readiness.md`](../audits/2026-10-20-production-readiness.md).

## Known gaps

- **Light only.** Dark mode per theme is Release 2; the `mode` modifier has no sources yet.
- **Export limits.** Semantic tokens are shared by every theme, so an advanced-panel override of a semantic token is listed in the export panel but is not in the files. Exported themes name their fonts but do not load them (see `docs/themes.md`). Five downloads for "Download all" (no zip).
- **Playground layout** was only checked at 320px and desktop widths, not at tablet widths in between. The colour inputs are native `type="color"`; alpha colours (the scrim) are text only.
- **No share URL** for a playground state (Release 4, D-052).
- **Not browser-tested here:** WebKit clipboard and Firefox clipboard (the copy test is Chromium only; the others only run the download path).
- **Open site/ops items for the maintainer:** the retired registry's Vercel project (`ui-design-system-registry`) may still need pausing or deleting; the Penpot boards were never made.
- Components not yet built: Textarea, Switch, Dialog, Toast, Tooltip, navigation (Releases 3 and 4).
